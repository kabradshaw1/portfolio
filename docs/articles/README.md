# LinkedIn Article Series

This directory contains LinkedIn-ready article drafts based on the Go and
Next.js portfolio sections.

## Format Strategy

Research notes used for these drafts:

- LinkedIn's own sharing guide recommends articles around 500-1,000 words,
  clear headlines, fresh perspectives, relevant hashtags, and cover images:
  https://content.linkedin.com/content/dam/help/linkedin/en-us/LinkedIn-Sharing-Guide.pdf
- LinkedIn's visibility guidance emphasizes specific professional insights,
  personal project lessons, early hooks, comments, and authentic consistency:
  https://www.linkedin.com/top-content/marketing/linkedin-content-and-ads/tips-for-increasing-visibility-with-linkedin-posts/
- LinkedIn talent-search research describes recruiter search as a mix of
  structured fields like canonical titles and skills plus free-text keywords:
  https://engineering.linkedin.com/content/dam/me/engineering/li-en/research/SIGIR-2018.pdf
- Software-engineering post examples tend to work best when framed as
  technical learnings, project launches, problem/solution stories, and
  opinionated architecture lessons:
  https://writio.ai/blog/linkedin-posts-software-engineer

The practical takeaway: write for humans, but include the search language
recruiters and hiring managers actually scan for: Go, Golang, microservices,
Kubernetes, gRPC, Kafka, RabbitMQ, PostgreSQL, observability, CI/CD, Next.js,
TypeScript, distributed systems, and production engineering.

## Posting Notes

- Use each file's "Feed post" section as the short LinkedIn post that links to
  or introduces the article.
- Use the "Article" section as the long-form LinkedIn article body.
- Add a concrete screenshot, architecture diagram, Grafana panel, trace view,
  or code snippet as the cover/rich media for stronger engagement.
- Keep hashtags to 3-5 relevant tags. Avoid broad hashtag stuffing.
- After posting, respond to comments with specific implementation details.
